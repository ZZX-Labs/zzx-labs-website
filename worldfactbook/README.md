# ZZX-WorldFactbook

`/worldfactbook/` is the public landing portal for the ZZX-WorldFactbook project family.

The page now follows the same structural model used by `/bitcoin/bitnodes/`:

1. ZZX-Labs sitewide header/navigation/footer from `/static/`.
2. A WorldFactbook-local header and footer loaded from `worldfactbook/includes/`.
3. A modular stylesheet loader (`styles.css`) with page-specific files under `worldfactbook/css/`.
4. A small JavaScript loader (`script.js`) with focused modules under `worldfactbook/js/`.
5. Static JSON/data contracts generated by `ZZX-WorldFactbook Crawler`.

## Project family

### ZZX-WorldFactbook

The historical core. Its goal is to preserve the public World Factbook corpus from 1962 through 2025, including country/territory records, leaders, maps, images, historical Fact of the Day and Image of the Day material, and other recoverable public features.

Historical source credit is retained for the Central Intelligence Agency and *The World Factbook*. ZZX-Labs is an independent preservation/continuation project and does not claim CIA affiliation or endorsement.

### ZZX-BritishWorldFactbook

The historical core plus clearly separated British public-source supplements from UK Government and archival sources, including appropriate FCDO, MoD, GCHQ, MI5, SIS/MI6, ONS, Parliament, National Archives, NATO, and UN material where publicly available.

### ZZX-GlobalWorldFactbook

The historical and British layers plus globally sourced public records such as UN, World Bank, IMF, NATO, national statistical offices, central banks, foreign ministries, and official national reference data. Conflicting source claims remain attributable rather than being silently merged.

### ZZX-HybridWorldFactbook

A provenance-first synthesis layer. TensorFlow models may learn historical organization and editorial style, but factual claims are intended to be retrieved from selected, dated, cited source records. Generated text must remain distinguishable from original historical CIA material.

## Current API compatibility

The landing page works with the files that already exist in the repository:

- `api/reference-index.json`
- `api/electricity-history.json`

When the full crawler output exists, it automatically upgrades to:

- `api/portal-index.json`
- `api/source-index.json`
- `api/media-index.json`
- `api/leaders/index.json`
- `api/facts-of-the-day/index.json`
- `api/images-of-the-day/index.json`

Missing feature indexes are reported as pending; the page does not fabricate replacement records.

## Attribution policy

Historical CIA material is labeled as historical CIA material. ZZX-generated continuation material must be labeled separately.

Recovered images retain the crawler citation-key filename contract and any explicit source credit. When no source credit is recoverable, the interface must say that the credit is unavailable rather than inferring one.

Third-party or partner material retains its own source/rights metadata even when it appears inside a U.S. government publication.

## Hosting

The landing page is plain HTML/CSS/JavaScript. It is designed for the existing ZZX-Labs GitHub Pages deployment and for local/nginx mirrors. No application server is required to render the page.


`/worldfactbook/` is the static public portal for the ZZX-WorldFactbook Crawler.

The portal does not scrape or parse source books in the browser. It consumes the normalized,
versioned JSON contracts generated by the crawler under `/worldfactbook/api/` and the normalized
media objects under `/worldfactbook/media/`.

## Public routes

- `/worldfactbook/` — historical portal
- `/worldfactbook/api/portal-index.json` — archive range and edition inventory
- `/worldfactbook/api/source-index.json` — source provenance index
- `/worldfactbook/api/editions/<year>/index.json` — edition manifest
- `/worldfactbook/api/editions/<year>/<category>.json` — normalized text chunks
- `/worldfactbook/api/media-index.json` — image/OCR index
- `/worldfactbook/api/media/<year>/index.json` — per-edition media records
- `/worldfactbook/api/attribution-index.json` — attribution inventory
- `/worldfactbook/api/attributions/<year>/images.json` — per-edition image citations
- `/worldfactbook/api/electricity-history.json` — verified Global Power Grid compatibility ledger
- `/worldfactbook/media/images/<year>/...png` — normalized image files
- `/worldfactbook/media/metadata/<year>/...json` — image metadata sidecars

## Front-end files

`worldfactbook.js` is the data-contract client. It resolves the local API root, caches JSON
responses, loads edition/category/media/attribution contracts, normalizes entity selectors, and
provides common filter helpers.

`script.js` owns the interface state and renders the year timeline, entity/category filters,
full-text search, normalized text rows, media/OCR gallery, source provenance, image citation modal,
and year-comparison view.

`style.css` contains the ZZX-Labs presentation layer and has no external framework dependency.

## Data behavior

The page treats `portal-index.json` as the source of truth for edition availability. Missing
editions remain visibly unresolved rather than receiving synthetic data.

Image credits follow the crawler's conservative attribution policy: a credit is displayed only when
it was explicitly recovered from the archived source. If no separate credit was printed or
recognized, the portal says so and retains source provenance instead.

Recovered media uses the crawler filename/citation convention:

`wfb-{edition}-{entity}-{category}-p{page:04d}-i{index:03d}-{sha12}.png`

The citation key is the filename stem.

## Hosting

The page is plain HTML/CSS/JavaScript and is suitable for GitHub Pages, nginx static hosting, local
mirrors, and offline archival deployments after the `/worldfactbook/api/` and
`/worldfactbook/media/` trees have been synchronized.

No server-side application is required for browsing the public corpus.
