# Mempool Visualizer

`mempool-visualizer` is the flagship wide-format ZZX-Labs Bitcoin HUD widget. It spans both dashboard columns and presents a pair of adjoining square blockspace chambers: the high-priority candidate field and the remaining visible reservoir. Every transaction is represented by square geometry. A permanent gapless square-dissection atlas remains beneath the animated layer, so spring motion, trails, pointer gravity, and block ripples never reveal blank cells.

## Runtime contract

The widget follows the canonical HUD contract:

- slot ID and manifest ID: `mempool-visualizer`
- widget root: `[data-widget-root="mempool-visualizer"]`
- assets: `widget.html`, `widget.css`, `widget.js`
- shared transport: `/__partials/widgets/_shared/zzx-mempool-live.js`
- activation: an `IntersectionObserver` starts data and animation only near the viewport
- suspension: rendering and the shared subscription stop off-screen or while the document is hidden

The integrated site already includes the slot, manifest entry, and full-width CSS selectors. For a manual port, add `<div class="btc-slot btc-slot--wide" data-widget="mempool-visualizer"></div>` to the HUD rail and add the same ID to `manifest.json`.

## Visual systems

The two chambers are exact square canvases placed edge-to-edge in the widget's 2:1 stage. The base atlas is generated by recursive 2×2 and 3×3 square dissection. Arbitrary transaction counts occasionally require a small number of marked continuation leaves; these repeat the smallest transaction while retaining a single transaction identity. The physical layer is then spring-integrated over that base.

Seven motion engines are included: Still Water, Tidal Field, Brownian Drift, Gravity Well, Quiet Orbit, Blockspace Breath, and Congestion Storm. Pointer movement can bend the field, a click emits a local impulse and pins the selected transaction, and a tip-height change emits a block ripple.

Forty themes are included in `themes.json`, grouped into ZZX, Tranquil, Celestial, Bitcoin, Terminal, Cipher, Signal, Regional, Ops, and Accessible collections. Ten scenario presets and six one-click macros are defined in `presets.json`. Presets cover calm observation, miner candidate inspection, fee pressure, whale watching, congestion, transaction age, hash structure, audit work, ambient display, and low-power operation.

## Macro console

Macros are whitespace-separated `key:value` assignments. Supported keys are `theme`, `physics`, `scale`, `color`, `topology`, `budget`, `fps`, `force`, `damping`, `trails`, `glow`, and `gap`.

Example:

```text
theme:aurora physics:tide scale:amount color:fee topology:spectrum budget:1536 fps:45 force:28 damping:91 trails:24 glow:52 gap:0.25
```

The Copy control serializes the current state to the same form. Export and Import use a versioned JSON settings document. Settings persist locally in the browser.

## Transaction readers

Selecting a square opens a persistent transaction reader. The reader retains the transaction ID, value, absolute fee, fee rate, virtual size, weight, input/output summaries, and a direct explorer link. Up to sixteen recent readers are stored locally and remain available after a transaction leaves the current field or after a page reload. Full transaction detail is requested only for explicitly selected transactions.

## Data behavior

The widget shares the existing site-wide WebSocket/REST mempool transport, preventing duplicate live connections. WebSocket projected-block transactions are preferred. REST recent transactions provide a bounded fallback. If neither source supplies a usable transaction field and Offline Demo Fallback is enabled, the widget clearly enters `DEMO FIELD`; deterministic demo values are never labeled live.

## Performance controls

Transaction budgets range from 256 to 4096 and frame caps from 20 to 60 FPS. Device pixel ratio is capped at 2. Glow, trails, labels, pointer gravity, and force are independently adjustable. Low Power mode uses 256 transactions, 20 FPS, no glow or trails, and reduced motion. The canvas never creates one DOM node per transaction.

## Local preview and test

Serve the site root over HTTP, then open `/__partials/widgets/mempool-visualizer/demo.html`. Run `node __partials/widgets/mempool-visualizer/tests/selftest.js` from the site root for structural validation.
